This page maps the fields Crustdata returns for companies and people to the CompanyEnrich V2 [company record](/docs/company-schema) and [person record](/docs/person-schema). Use it to rewrite the code that reads Crustdata responses and to migrate the records you stored.

Company fields come from Company Enrich and Company Search. Person fields come from Person Enrich, Person Search, and Contact Enrich. Crustdata paths are relative to `company_data` or `person_data` in enrichment responses, and to each item of `companies` or `profiles` in search responses.

The same mapping is available as JSON at [/migrations/crustdata.json](https://docs.companyenrich.com/migrations/crustdata.json), for scripts and [coding agents](/docs/migrate-from-crustdata-agent).

## How to read this page

Paths use dots for nested objects and `[]` for arrays, as in `experiences[].company.domain`. **Expand** names the [expansion](/docs/credits#expansions) you must request to get the field. Each one adds credits.

Crustdata returns the sections you name in `fields`, and only `basic_info` by default. CompanyEnrich always returns the base record and adds the expansions you name in `expand`. So a Crustdata `fields` list becomes an `expand` list that holds only the expansions your code reads.

**Fidelity** describes how the definitions compare:

{/* generated: crustdata fidelity */}

| Fidelity | Meaning |
| --- | --- |
| `same` | Same meaning and format. |
| `renamed` | Same meaning and values under a different name or label. |
| `transformed` | Same information in a different format, casing, or structure. Convert it in code. |
| `lossy` | Related but not equivalent. Values can differ, so check the fields your code depends on. |
| `none` | No CompanyEnrich equivalent. |

{/* end generated */}

Fidelity compares definitions, not data. The two providers build their records from different sources, so a value can differ even when the fields mean the same thing.

## Person fields

Fields under **Current job** come from the person's current experiences. Crustdata splits jobs into `current` and `past` lists. CompanyEnrich returns one `experiences` list, and marks current jobs with `isCurrent`. A person can have more than one current job. After an email lookup, the experience at the email's company has `isMatched` set to `true`.

Fields under **Contact** come from [`GET /v2/people/{personId}/email`](/api-reference/v2/get-people-personid-email), a separate call.

### Country

Crustdata returns full country names, such as `United States`. Its company filters also take ISO 3166-1 alpha-3 codes, such as `USA`. CompanyEnrich returns `location.country.code`, an ISO 3166-1 alpha-2 code such as `US`, and `location.country.name`, and filters on the alpha-2 code. To convert stored names or alpha-3 codes, look up the codes with [`POST /v2/geo/countries`](/api-reference/v2/post-geo-countries), which is free.

### Growth periods

Crustdata enrichment keys headcount growth by `mom`, `qoq`, `six_months`, `yoy`, and `two_years`, and search uses `1m`, `3m`, `6m`, and `12m`. CompanyEnrich filters on growth with `workforceGrowth` periods `m6`, `y1`, and `y2`, as a ratio: 20% growth is `0.2`. To read growth for one company, compare two points from [`GET /v2/companies/workforce`](/api-reference/v2/get-companies-workforce).
