This guide is for engineers whose code, scripts, or AI agents call the Crustdata API and are moving some or all of those calls to the CompanyEnrich V2 API. It maps each Crustdata endpoint, lists the behavior that changes in your code, and shows how to check the result on records you already have before you switch traffic.

<Note>
  Crustdata behavior on these pages was checked against Crustdata's public documentation for API version `2025-11-01` on November 23, 2026. The legacy `/screener` and `/data_lab` endpoints are not covered. CompanyEnrich behavior comes from the [V2 API reference](/api-reference/v2/overview). The full mapping is also available as JSON at [/migrations/crustdata.json](https://docs.companyenrich.com/migrations/crustdata.json).
</Note>

## Switch company enrichment in five minutes

This is the shortest path: one enrichment call by domain, moved to the V2 API with the Python SDK.

<Steps>
  <Step title="Get an API key">
    Create a key at [app.companyenrich.com/access-keys](https://app.companyenrich.com/access-keys) and export it as `COMPANYENRICH_API_KEY`. Check it with [`GET /v2/me`](/api-reference/v2/get-me), which is free:

    ```bash
    curl https://api.companyenrich.com/v2/me \
      -H "Authorization: Bearer $COMPANYENRICH_API_KEY"
    ```
  </Step>
  <Step title="Install the SDK">
    ```bash
    pip install companyenrich
    ```

    The [Python SDK](/docs/python-sdk) needs Python 3.10 or later. There are also SDKs for [JavaScript](/docs/javascript-typescript-sdk), [Ruby](/docs/ruby-sdk), and [PHP](/docs/php-sdk), and a [CLI](/docs/cli).
  </Step>
  <Step title="Replace the call">
    <CodeGroup>

    ```python Before (Crustdata)
    import os

    import requests

    response = requests.post(
        "https://api.crustdata.com/company/enrich",
        headers={
            "authorization": f"Bearer {os.environ['CRUSTDATA_API_KEY']}",
            "x-api-version": "2025-11-01",
        },
        json={"domains": ["stripe.com"], "fields": ["basic_info", "headcount"]},
    )
    matches = response.json()[0]["matches"]
    if matches:
        company = matches[0]["company_data"]
        info = company["basic_info"]
        print(info["name"], company["headcount"]["total"], info["professional_network_url"])
    ```

    ```python After (CompanyEnrich)
    from companyenrich import CompanyEnrich, NotFoundError

    client = CompanyEnrich()  # reads COMPANYENRICH_API_KEY

    try:
        company = client.companies.enrich("stripe.com")
        socials = company.get("socials") or {}
        print(company.get("name"), company.get("employees"), socials.get("linkedinUrl"))
    except NotFoundError:
        company = None  # no match, not charged
    ```

    ```bash cURL
    curl "https://api.companyenrich.com/v2/companies/enrich?domain=stripe.com" \
      -H "Authorization: Bearer $COMPANYENRICH_API_KEY"
    ```

    </CodeGroup>
  </Step>
  <Step title="Update the fields you read">
    | Crustdata field | CompanyEnrich field | Change |
    | --- | --- | --- |
    | `basic_info.name` | `name` | Renamed |
    | `basic_info.primary_domain` | `domain` | Renamed |
    | `basic_info.year_founded` | `foundedYear` | Renamed |
    | `headcount.total` | `employees`, or `workforce.observedEmployeeCount` with `expand=workforce` | A range such as `1K-5K`, or a count with the expansion |
    | `locations.country` | `location.country.name` or `location.country.code` | Name in source casing, or an ISO alpha-2 code |
    | `basic_info.professional_network_url` | `socials.linkedinUrl` | Renamed |

    The [field mapping](/docs/migrate-from-crustdata-field-mapping) covers every other field.
  </Step>
  <Step title="Handle no match">
    Crustdata returns `200` with an empty `matches` array. CompanyEnrich returns `404`, and the SDK raises `NotFoundError`. Neither API charges for it.
  </Step>
</Steps>

## What takes longer

| Workload | Why | Guide |
| --- | --- | --- |
| Search filters | Crustdata takes a tree of conditions with `and` and `or`. CompanyEnrich takes a flat `filter` in which every filter must match, with no sorting. | [Search filters](/docs/migrate-from-crustdata-search) |
| Person lookups | CompanyEnrich enriches a person by work email, not by profile URL. Search results are full records, so a search-then-enrich flow becomes one search. | [People](#people) |
| Stored records | Crustdata IDs do not carry over, and value labels change, such as `Privately Held` to `private`. | [Field mapping](/docs/migrate-from-crustdata-field-mapping) |
| Field selection | Crustdata `fields` lists the sections to return. CompanyEnrich returns the base record and adds paid expansions. | [Field selection](#field-selection) |
| Contact data | CompanyEnrich finds work emails only, one person at a time, by CompanyEnrich person ID. | [People](#people) |
| AI agents and scripts | MCP tools and CLI commands change. | [Move your MCP setup](#move-your-mcp-setup) |

## Move your MCP setup

If your agent uses the Crustdata MCP server, add the CompanyEnrich server. The hosted server is at `https://mcp.companyenrich.com/mcp`. For example, in Claude Code:

```bash
claude mcp add --transport http companyenrich https://mcp.companyenrich.com/mcp
```

The [MCP server guide](/docs/mcp-server) covers Claude Desktop, Cursor, VS Code, and other clients, and lists the credits each tool uses. Then update any prompts or code that name Crustdata tools:

{/* generated: crustdata mcp */}

| Crustdata tool | CompanyEnrich tool | Notes |
| --- | --- | --- |
| Identify or enrich a company | `enrich_company` or `enrich_company_by_properties` | By domain, or by name or social profile. Use `expand` to request `technologies`, `keywords`, or `financial` (funding). |
| Company headcount and growth | `get_company_workforce` | Headcount by department, with monthly history. |
| Search companies | `search_companies` | Use `filter` for structured criteria, `semantic.query` for a description, or `lookalike.domains` for 1 to 10 seed domains. |
| Search people | `search_people` | By name, title, seniority, department, country, and employer. |
| Enrich a person or identify one from an email | `lookup_person_by_email` or `get_person_by_id` | By work email, or by a CompanyEnrich person ID from search. No lookup by profile URL. |
| Contact enrichment | `enrich_person_email` | Work email only. No personal emails or phone numbers. |
| Credit balance | `get_current_user` | Free. |
| Jobs, social posts, web search and fetch, watches, and batch jobs | None | No equivalent tools. |

{/* end generated */}

CompanyEnrich tools take plain values, such as a domain or a job title, so your agent does not need to look up autocomplete values first.

### Scripts that use the Crustdata CLI

The [CompanyEnrich CLI](/docs/cli) covers the same company and people workflows. Its search flags are named after the CompanyEnrich filters, so rewrite each `--filter` as a flag, or send the full request body with `companyenrich api`.

| Crustdata CLI | CompanyEnrich CLI |
| --- | --- |
| `crustdata company enrich --domains stripe.com` | `companyenrich company enrich stripe.com` |
| `crustdata company identify` | `companyenrich company enrich --name "..."`, or `company autocomplete <domain prefix>` |
| `crustdata company search --filter '...'` | `companyenrich company search` with flags such as `--country US`, or `--semantic "..."` |
| `crustdata person search` | `companyenrich people search` |
| `crustdata person contacts` | `companyenrich people email <id>`, for a work email |
| `crustdata batch company enrich` | `companyenrich company bulk-enrich -f domains.txt --wait` |
| `crustdata account credits` | `companyenrich me` |
| `--jq` | `--fields`, or `--format json` piped to `jq` |

A CompanyEnrich lookup that finds nothing exits with code 4, where Crustdata prints an empty `matches` array. Handle that code in scripts that use `set -e`, or the script stops at the first unknown domain.

## Endpoint mapping

Crustdata enrichment and identify take arrays of one identifier type. CompanyEnrich takes one company or person per request, except batch enrichment, which takes up to 50 domains. Where a Crustdata call takes `crustdata_company_ids`, send the company's domain, or the CompanyEnrich ID, instead. Crustdata IDs cannot be converted.

## Request and response differences

### Authentication

| | Crustdata | CompanyEnrich |
| --- | --- | --- |
| Headers | `authorization: Bearer YOUR_CRUSTDATA_API_KEY` and `x-api-version: 2025-11-01` | `Authorization: Bearer YOUR_API_TOKEN`. There is no version header; the version is in the path, `/v2`. |
| SDK | None. Calls use HTTP directly, or the `crustdata` CLI. | `CompanyEnrich()` reads `COMPANYENRICH_API_KEY`, or takes the key as its first argument |

### Response shape

| Call | Crustdata | CompanyEnrich |
| --- | --- | --- |
| Enrichment and identify | A top-level array, one entry per identifier, each with `matched_on`, `match_type`, and `matches`, where each match has a `confidence_score` and `company_data` or `person_data` | The record is the body |
| Several domains at once | One enrichment request with several `domains`, one array entry each | [`POST /v2/companies/enrich/batch`](/api-reference/v2/post-companies-enrich-batch) with up to 50 domains. `items` come back in request order, each with `domain`, `status`, and `company` when `status` is `found`. |
| Search | `companies` or `profiles`, `next_cursor`, and `total_count` | `items` and `nextCursor`. Get totals from the free count endpoint. |
| Bulk jobs | `GET /batch/{batch_id}` with `status` and a `download_url` for a gzipped JSONL file | `GET /v2/batches/{id}`, then results as JSON, NDJSON, or CSV |
| Errors | `error` with `type`, `message`, and `metadata` | A problem document with `type`, `title`, `status`, and `detail`. `422` adds `errors` per field. The `x-trace-id` header identifies the request. |

### Field selection

Crustdata returns only the sections you list in `fields`. Company enrichment defaults to `basic_info`, and search defaults to every field. CompanyEnrich always returns the base record. The company base record includes name, domain, description, industry, size and revenue ranges, location, and social profiles. Add `financial`, `keywords`, `naicsCodes`, `technologies`, or `workforce` with `expand`, and `company` or `education` on a person.

When you rewrite a call, turn its `fields` list into an `expand` list that holds only the expansions your code reads. Each expansion adds credits.

### Match confidence

Crustdata returns candidate matches for each identifier, each with a `confidence_score`, and an empty `matches` array when there is none. Person lookups also report a `match_status` of `matched`, `not_found`, or `redacted`.

CompanyEnrich has no score:

* Enrichment by domain looks up that domain.
* Enrichment by properties requires every property you send to match. If several companies match, it returns the highest-ranked one.
* A person lookup by work email returns the person, or `404`.

Code that accepts or rejects a match by `confidence_score` needs a new rule, because there is no score to check. For name lookups, send a domain instead, or add a profile URL as `linkedinUrl` to the name so that both must match.

### Status codes

| Status | Crustdata | CompanyEnrich |
| --- | --- | --- |
| `200` | A match, an enrichment with an empty `matches` array, or a search that ran | A match, or a search that ran |
| `400` | Invalid request, including an unknown field, a wrong operator, or a stale cursor | Malformed request |
| `401` | Missing or invalid key | Missing or invalid key |
| `402` | Out of credits | Out of credits, or the plan does not include the request. Do not retry. |
| `403` | The key may not call this endpoint, or a requested field is not enabled | The key may not perform this request |
| `404` | Defined, but a missed match usually returns `200` | No match. Not charged. |
| `422` | Not documented | Validation failed. `errors` lists the messages per field. |
| `429` | Rate limit hit, or too many active batch jobs | Rate limit hit. Wait for the time the response gives. |
| `5xx` | Server error | Server error |

The change that needs code is the missed match: Crustdata reports it inside a `200` response, while CompanyEnrich returns `404`. The SDK raises a typed exception for each non-2xx status, such as `NotFoundError`, `PaymentRequiredError`, and `RateLimitError`.

### Billing behavior that affects your code

These differences change how you write retries, guards, and tests. Prices for each endpoint are in [Credits](/docs/credits).

* **No match is free on both APIs.** CompanyEnrich enrichment that finds nothing returns `404` and is not charged.
* **An empty search is charged.** Crustdata charges per result, so a search with no results costs nothing. CompanyEnrich charges one result's base price, such as 1 credit for a filter search. Check a new filter with the free [count endpoint](/api-reference/v2/post-companies-search-count) first.
* **Extra company fields are expansions.** Each one you request adds 1 credit per company returned, so request only the ones your code reads.
* **Work emails are a separate call.** [`GET /v2/people/{personId}/email`](/api-reference/v2/get-people-personid-email) costs 10 credits only when it finds an email your account has not accessed before.
* **Responses report their cost.** Read `x-credit-cost` and `x-credit-remaining` from the response headers, in place of `X-Credits-Used`.

### Pagination

| | Crustdata | CompanyEnrich |
| --- | --- | --- |
| Page size | `limit`, up to 1,000 for a filter search and 100 for a ranked search | `pageSize`, 1 to 100 |
| Next page | Send the `next_cursor` from the last response as `cursor`, until it is `null` | Send the `nextCursor` from the last response as `cursor`, until it is omitted |
| Cursor lifetime | 20 minutes for a ranked search | 24 hours after the first page |

Crustdata asks for `sorts` to keep filter-search pages stable. CompanyEnrich has no sorting, so page with the cursor. If your code needs a sorted list, fetch every page, then sort. The Python SDK pages for you with `search_all()`. A cursor from one API does not work in the other, so restart any paging job from the first page.

### Rate limits

Crustdata limits each endpoint by requests per minute, set by your plan, and reports `x-ratelimit-limit`, `x-ratelimit-remaining`, and `x-ratelimit-reset`. CompanyEnrich applies a global limit of 500 requests per minute per IP address and a per-route limit from your plan, reported in `x-ratelimit-limit`, `x-ratelimit-remaining`, and `x-ratelimit-window`. A batch of 50 domains is one request. The SDKs wait and retry on `429`. See [Rate limits](/docs/rate-limit).

### Values and URLs

| | Crustdata | CompanyEnrich |
| --- | --- | --- |
| Countries | Full names, such as `United States`. Company filters also take ISO alpha-3 codes, such as `USA`. | `code` (ISO 3166-1 alpha-2, such as `US`) and `name` |
| Company types | Labels such as `Privately Held` | Values such as `private` |
| Size ranges | `myself only`, `2-10`, through `10001+` | `1-10` through `over-10K` |
| Seniority and function | Labels such as `Vice President` and `Engineering` | Values such as `vp` and `engineering-technical` |
| Headcount | A count, `headcount.total` | A range, `employees`, or a count with `expand=workforce` |

The [value translations](/docs/migrate-from-crustdata-field-mapping#value-translations) list every value.

### IDs

Crustdata IDs and CompanyEnrich IDs are separate. Crustdata company and person IDs are integers. CompanyEnrich company IDs are UUIDs, and person IDs are 64-bit integers, so keep them in separate columns. Store the CompanyEnrich ID next to the Crustdata ID, and re-key company data on its domain.

## Verify parity on your own data

Before you move production traffic, measure CompanyEnrich on records you already have. This makes no Crustdata requests.

<Steps>
  <Step title="Check your key and plan">
    Call [`GET /v2/me`](/api-reference/v2/get-me). It is free and returns your balance and plan capabilities.
  </Step>
  <Step title="Size your searches for free">
    Send each translated filter to the [company](/api-reference/v2/post-companies-search-count) or [people](/api-reference/v2/post-people-search-count) count endpoint and compare `total` with Crustdata's `total_count`.
  </Step>
  <Step title="Pick a sample">
    Take 100 to 200 `company_data` records you already stored from Crustdata. Using stored records means you spend no Crustdata credits. CompanyEnrich charges 1 credit per company found.
  </Step>
  <Step title="Compare the fields you read">
    Run the script below on the sample. It enriches the domains in batches of 50 and sorts each field into `equal`, `differ`, `only Crustdata`, `only CompanyEnrich`, or `both empty`. Fields marked `lossy` in the [field mapping](/docs/migrate-from-crustdata-field-mapping) differ by definition, so leave them out or compare them by hand.
  </Step>
  <Step title="Check searches and people">
    For each translated search, run the count, then a [preview](/api-reference/v2/post-companies-search-preview) if your plan includes it, then one page. For person lookups, test work emails you already know.
  </Step>
</Steps>

<Accordion title="compare.py" icon="code">

```python compare.py
"""compare.py: compare stored Crustdata company records with CompanyEnrich on the same domains.

Usage: python compare.py crustdata_companies.jsonl   (one stored company_data object per line)
Costs 1 CompanyEnrich credit per company found. Makes no Crustdata requests.
"""

import json
import sys
from collections import Counter

from companyenrich import CompanyEnrich

TYPES = {"Privately Held": "private", "Public Company": "public", "Nonprofit": "nonprofit",
         "Educational Institution": "educational", "Government Agency": "government",
         "Self-Employed": "self-employed", "Sole Proprietorship": "self-owned", "Partnership": "partnership"}

# Crustdata path -> (how to read the comparable CompanyEnrich value, how to convert the Crustdata value)
FIELDS = {
    "basic_info.name": (lambda c: c.get("name"), None),
    "basic_info.primary_domain": (lambda c: c.get("domain"), None),
    "basic_info.year_founded": (lambda c: c.get("foundedYear"), None),
    "basic_info.company_type": (lambda c: c.get("type"), TYPES.get),
    "basic_info.professional_network_url": (lambda c: (c.get("socials") or {}).get("linkedinUrl"), None),
    "locations.country": (lambda c: ((c.get("location") or {}).get("country") or {}).get("name"), None),
    "locations.state": (lambda c: ((c.get("location") or {}).get("state") or {}).get("name"), None),
}


def crustdata_value(record, path):
    for key in path.split("."):
        record = (record or {}).get(key)
    return record


def normalize(value):
    if isinstance(value, str):
        value = value.lower().removeprefix("https://").removeprefix("http://").removeprefix("www.").rstrip("/")
    return value or None


def outcome(crustdata, ce):
    if crustdata is None and ce is None:
        return "both empty"
    if ce is None:
        return "only Crustdata"
    if crustdata is None:
        return "only CompanyEnrich"
    return "equal" if crustdata == ce else "differ"


def main(path, client=None):
    records = [json.loads(line) for line in open(path) if line.strip()]
    records = [record for record in records if crustdata_value(record, "basic_info.primary_domain")]
    client = client or CompanyEnrich()  # reads COMPANYENRICH_API_KEY
    results = Counter()
    for start in range(0, len(records), 50):
        chunk = records[start:start + 50]
        batch = client.companies.enrich_batch([record["basic_info"]["primary_domain"] for record in chunk])
        for record, item in zip(chunk, batch["items"], strict=True):
            if item["status"] != "found":
                results[f"lookup: {item['status']}"] += 1
                continue
            for field, (read, convert) in FIELDS.items():
                value = crustdata_value(record, field)
                if convert and value is not None:
                    value = convert(value)
                results[f"{field}: {outcome(normalize(value), normalize(read(item['company'])))}"] += 1
    for key, count in sorted(results.items()):
        print(f"{key:55} {count}")
    return results


if __name__ == "__main__":
    main(sys.argv[1])
```

## Cut over

* Put the CompanyEnrich path behind a feature flag and keep Crustdata as the fallback until the parity results meet the thresholds you set.
* Store CompanyEnrich IDs next to Crustdata IDs.
* Log `x-credit-cost` per call while both paths run.
* Move reads first, then writes to stored records, then remove the Crustdata calls, keys, and MCP configuration you no longer use.

## When to keep Crustdata

Keep Crustdata, or another source, for these workloads:

* Person enrichment and identify by profile URL, and lookups by Google Scholar URL.
* Personal emails, phone numbers, and bulk contact enrichment.
* Live search, live profile retrieval, and work-history verification.
* Job postings, social posts, web search and fetch, watches and webhooks, and agent search.
* Company sections such as web traffic, SEO, reviews, news, followers, hiring, and key people inside the company record.
* Searches that need OR across different fields, sorting, radius or polygon areas, SIC codes, skills, or technology categories.

People searches support state and city IDs, but inclusion filters match only people whose reported location has been resolved to those places. Check coverage before replacing a location-based search. See [People search patterns](/docs/migrate-from-crustdata-search#people-search-patterns).

You can run both APIs side by side and route each call by the [endpoint mapping](#endpoint-mapping).

## Common questions

<AccordionGroup>
  <Accordion title="Can I keep using my Crustdata IDs?">
    No. Store the CompanyEnrich ID alongside the Crustdata ID, and re-key company data on its domain.
  </Accordion>
  <Accordion title="Can I enrich a person by profile URL?">
    No. CompanyEnrich enriches a person by work email with [`POST /v2/people/enrich`](/api-reference/v2/post-people-enrich), and people search returns full records. Keep Crustdata for profile URL lookups.
  </Accordion>
  <Accordion title="Do I need to list fields?">
    No. The base record always comes back. List only the paid expansions your code reads in `expand`.
  </Accordion>
  <Accordion title="Is there a confidence score?">
    No. See [Match confidence](#match-confidence).
  </Accordion>
  <Accordion title="How do I get the total number of results?">
    Send the same filter to the free count endpoint. Search responses do not include a total.
  </Accordion>
  <Accordion title="Can I sort search results?">
    No. Results come in relevance order. Sort them in your code.
  </Accordion>
  <Accordion title="Do batch and bulk enrichment need a specific plan?">
    No. Batch and bulk enrichment work on every plan.
  </Accordion>
</AccordionGroup>
