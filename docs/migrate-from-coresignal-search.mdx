Coresignal searches take either an Elasticsearch DSL query, a tree of `bool` clauses on index fields, or Search Filters, a flat object of named parameters. Both return record IDs. CompanyEnrich V2 search takes a flat `filter` object in which every filter must match, and returns full records. Most clauses translate to one filter, but the field names, value formats, and operators differ. This page shows each pattern and the clauses that have no equivalent.

A translation that silently drops a clause returns, and charges for, the wrong records. Translate each clause, and check the result with the free count endpoint.

## How the two search models differ

| | Coresignal | CompanyEnrich |
| --- | --- | --- |
| Request | An Elasticsearch DSL `query`, or Search Filters parameters such as `hq_country_iso2` and `employees_count_gte` | `filter`, an object with one key per filter. Company search also takes `semantic` or `lookalike`; people search takes `semantic` and a `company` query. |
| Combining conditions | Any mix of `must`, `filter`, `should`, and `must_not`, nested. Search Filters combine parameters with AND. | Every filter must match. Within a filter, `in` matches any value and `notIn` excludes values. A plain array matches any value, except on `keywords`, `technologies`, and `categories`, where it requires every value. There is no OR across different filters. |
| Operators | Elasticsearch queries such as `term`, `match`, `match_phrase`, `range`, `nested`, `exists`, `wildcard`, and `query_string`. Search Filters use `_gte` and `_lte` suffixes, an `exclude_` prefix, and `\|`, `+`, and `-` in text. | A value or an array, `in` and `notIn` rules, `min` and `max` ranges, `after` and `before` dates, and `require` for features a company must have |
| Field names | Index fields, such as `hq_country_iso2` and `experience.position_title` | Filter names, such as `country` and `position`. They are listed in the [company filters](/docs/company-search-api-filters) and [people filters](/docs/people-search-api-filters). |
| Values | Labels such as `Privately Held`, `51-200 employees`, and `C-Level` | Exact values from [field values](/docs/field-values), ISO alpha-2 country codes, and IDs from the free lookup endpoints |
| Results | IDs, up to 1,000 per page, then a collect call per record | Full records, up to 100 per page |
| Sorting | `_score`, `id`, or a numeric field | None. Results come in relevance order. |
| Totals | The `x-total-results` header | The free [company](/api-reference/v2/post-companies-search-count) and [people](/api-reference/v2/post-people-search-count) count endpoints |

## Translate a search in four steps

<Steps>
  <Step title="Flatten the query">
    Write down each leaf clause with its field, query type, and value. Clauses in `must` and `filter` must all match. Note every `should` group: a `should` across different fields cannot be sent as one CompanyEnrich search. Clauses in `must_not`, and Search Filters parameters that start with `exclude_`, become exclusions.
  </Step>
  <Step title="Map each clause">
    Find the pattern for the field in the tables below. A pattern applies whatever the clause's query type: `term`, `terms`, `match`, and `match_phrase` on the same field translate the same way, as does the Search Filters parameter the note names. The exception is `match_phrase` on a title field sent to a `semantic_search` endpoint, which adds synonyms that CompanyEnrich does not: see [Semantic and agentic search](#semantic-and-agentic-search). Convert values with the [value translations](/docs/migrate-from-coresignal-field-mapping#value-translations), and look up IDs and names with the free [geo](/api-reference/v2/post-geo-states), [industry](/api-reference/v2/get-industries), [keyword](/api-reference/v2/get-keywords-autocomplete), [technology](/api-reference/v2/get-technologies-autocomplete), and [position](/api-reference/v2/get-positions-autocomplete) endpoints.
  </Step>
  <Step title="Count it for free">
    Send the filter to the [company](/api-reference/v2/post-companies-search-count) or [people](/api-reference/v2/post-people-search-count) count endpoint. Compare `total` with the `x-total-results` you recorded from Coresignal. A large gap usually means a clause was dropped or a value was not converted.
  </Step>
  <Step title="Fetch one page">
    Run the search with a small `pageSize` and check the records against what you expect. An empty search still costs one result's base price.
  </Step>
</Steps>

For example, this Coresignal query:

<CodeGroup>

```json Elasticsearch DSL
{
  "query": {
    "bool": {
      "must": [
        { "match": { "hq_country_iso2": "US" } },
        { "terms": { "size_range": ["51-200 employees", "201-500 employees"] } },
        { "range": { "founded_year": { "gte": 2020 } } },
        { "terms": { "last_funding_round.type": ["Series A", "Series B"] } }
      ],
      "must_not": [
        { "term": { "type": "Nonprofit" } }
      ]
    }
  }
}
```

```json Search Filters
{
  "hq_country_iso2": "US",
  "size_range": ["51-200 employees", "201-500 employees"],
  "founded_year_gte": 2020,
  "last_funding_round_type": ["Series A", "Series B"],
  "exclude_type": "Nonprofit"
}
```

</CodeGroup>

becomes this CompanyEnrich search:

<CodeGroup>

```bash cURL
curl -X POST https://api.companyenrich.com/v2/companies/search \
  -H "Authorization: Bearer $COMPANYENRICH_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "pageSize": 100,
    "expand": ["financial"],
    "filter": {
      "country": "US",
      "reportedEmployees": ["51-200", "201-500"],
      "foundedYear": { "min": 2020 },
      "fundingRounds": ["series_a", "series_b"],
      "type": { "notIn": ["nonprofit"] }
    }
  }'
```

```python Python
from companyenrich import CompanyEnrich

client = CompanyEnrich()  # reads COMPANYENRICH_API_KEY

query = {
    "country": "US",
    "reportedEmployees": ["51-200", "201-500"],  # the self-reported range, like size_range
    "foundedYear": {"min": 2020},
    "fundingRounds": ["series_a", "series_b"],
    "type": {"notIn": ["nonprofit"]},
}

print(client.companies.count(filter=query)["total"])  # free
page = client.companies.search(filter=query, page_size=100, expand=["financial"])
for company in page["items"]:
    print(company["name"], company["domain"], (company.get("financial") or {}).get("fundingStage"))
```

</CodeGroup>

The results are full company records, so the collect calls that followed the Coresignal search go away. Funding is an expansion, so the request adds `expand` only because the code reads `fundingStage`.

## How clause types translate

| Coresignal clause | CompanyEnrich |
| --- | --- |
| `bool.must` and `bool.filter`, or several Search Filters parameters | Put each clause in `filter`. Every filter must match. |
| `bool.should` on one field, or a list value in Search Filters | An `in` rule on that filter. A plain array works too, except on `keywords`, `technologies`, and `categories`, where it requires every value. |
| `bool.should` across different fields | No equivalent. Run one search per branch and merge the results on `id`. |
| `bool.must_not`, or an `exclude_` parameter | `notIn` on the same filter |
| `term`, `terms`, `match`, and `match_phrase` | The value, or an array of values, on the field's filter |
| `range` with `gte` and `lte`, or `_gte` and `_lte` parameters | `min` and `max`, which are inclusive. For `gt` and `lt` on whole numbers, such as counts and years, move the bound by one. Date filters take date-times, such as `2026-08-01T00:00:00Z`. |
| `nested` on `experience`, `education`, or `technologies_used` | Map the inner clause by its field. On `experience`, `active_experience` set to `1` points to the current-job filters, and `0` to `pastExperience`. |
| `exists` | `require`, for the 13 features it covers |
| `query_string`, `wildcard`, `prefix`, `fuzzy`, and `multi_match` | Only where CompanyEnrich has a text filter: `query` for names, `keywords`, and `position`. Otherwise no equivalent. |
| `sort` | Drop `_score`. Other sorts have no equivalent. |
| `\|`, `+`, and `-` in Search Filters text | `in`, an array, and `notIn`. For `keywords` and `technologies`, an array requires every value. |

## People search patterns

Person filters such as `domain`, `position`, `seniority`, and `department` match the person's current job. Conditions on the employer, such as its size, industry, or headquarters country, go in a `company` query, which takes the [company search filters](/docs/company-search-api-filters). Past jobs go in `pastExperience`.

Coresignal's `experience` fields cover current and past jobs, so check how a nested clause treats `experience.active_experience`. Search Filters parameters that start with `experience_` match past or current jobs, which CompanyEnrich splits between the current-job filters and `pastExperience`.

Use `filter.state` and `filter.city` for the person's location. They take integer IDs from the free [state](/api-reference/v2/post-geo-states) and [city](/api-reference/v2/post-geo-cities) endpoints, also returned as `location.state.id` and `location.city.id`. A single ID, an array, or an `in` rule matches only people whose reported location has been resolved to those places. A `notIn` exclusion keeps people without a resolved state or city. Compare coverage before replacing a search that depends on location text.

## Clauses that do not translate

* **OR across different fields.** Run one search per branch and merge the results on `id`. OR across values of one field works: send `in`.
* **Sorting.** Sort the records in your code. To reproduce a top list, such as the largest companies, count the matches for free, fetch every page, then sort.
* **Text queries on most fields.** `query_string`, `wildcard`, `fuzzy`, and phrase matching translate only where CompanyEnrich has a text filter: `query` for names, `keywords`, and `position`. Descriptions, headlines, summaries, and location text have no filter.
* **Job postings, followers, web traffic, reviews, salaries, SIC codes, and technology dates.**
* **Skills, certifications, career length, employment status, and social activity.**
* **`exists` checks**, except the 13 company features `require` covers, such as `anyFunding` and `linkedin`.
* **Index details**, such as `.exact` and `.domain_only` subfields, `boost`, and `function_score`. Map the clause by its field and drop the rest.

## Totals and pagination

Search responses do not include a total. The free count endpoints return `total`, the number of matching records, and `count`, the number your plan lets you retrieve.

Pages hold 1 to 100 full records, set with `pageSize`, against up to 1,000 IDs per Coresignal page. Pass the `nextCursor` of one page as `cursor` to get the next, until `nextCursor` is omitted. A cursor expires 24 hours after the first page. A Coresignal `after` value does not work on CompanyEnrich, so restart any paging job from the first page.

## Semantic and agentic search

Coresignal's `semantic_search` endpoints add job titles with the same meaning to `match_phrase` clauses on title fields. CompanyEnrich `position` matches the phrase inside current titles but does not add synonyms. List the variants you want, such as `["software engineer", "software developer"]`, or describe the people in a [semantic people search](/docs/people-search-api).

If your code sends a prompt to Coresignal's Agentic Search API, send the same text as a semantic query:

```json
{
  "semantic": { "query": "developer tooling companies building observability products" },
  "filter": { "country": "US" }
}
```

Semantic search ranks results by meaning and reports the filters it inferred in `interpretation`. It returns records, not a generated query. It costs 2 credits per company returned instead of 1. For companies like ones you already know, use a [lookalike search](/docs/similar-companies-api), which takes up to 10 seed domains and costs 5 per company.
