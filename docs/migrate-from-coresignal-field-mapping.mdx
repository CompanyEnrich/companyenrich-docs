This page maps the fields Coresignal's Multi-source Company and Employee APIs return to the CompanyEnrich V2 [company record](/docs/company-schema) and [person record](/docs/person-schema). Use it to rewrite the code that reads Coresignal responses and to migrate the records you stored.

Company fields come from Company collect, enrich, and Bulk Collect. Person fields come from Employee collect and enrich, and from the Contact Enrichment API. Base and Clean records use other field names and are not covered.

The same mapping is available as JSON at [/migrations/coresignal.json](https://docs.companyenrich.com/migrations/coresignal.json), for scripts and [coding agents](/docs/migrate-from-coresignal-agent).

## How to read this page

Paths use dots for nested objects and `[]` for arrays, as in `experiences[].company.domain`. **Expand** names the [expansion](/docs/credits#expansions) you must request to get the field. Each one adds credits.

Coresignal returns the full record, or the core bundle plus the bundles you name. CompanyEnrich always returns the base record and adds the expansions you name in `expand`. So a Coresignal `bundle` or `fields` list becomes an `expand` list that holds only the expansions your code reads.

Coresignal's documentation and its OpenAPI specification spell some fields differently: `professional_network_url` and `linkedin_url`, `financial_website_url` and `crunchbase_url`, and `company_id` and `id`. Rows list both spellings. Match whichever your code reads.

**Fidelity** describes how the definitions compare:

{/* generated: coresignal fidelity */}

| Fidelity | Meaning |
| --- | --- |
| `same` | Same meaning and format. |
| `renamed` | Same meaning and values under a different name or label. |
| `transformed` | Same information in a different format, casing, or structure. Convert it in code. |
| `lossy` | Related but not equivalent. Values can differ, so check the fields your code depends on. |
| `none` | No CompanyEnrich equivalent. |

{/* end generated */}

Fidelity compares definitions, not data. The two providers build their records from different sources, so a value can differ even when the fields mean the same thing.

## Person fields

Fields under **Current job** come from the person's current experience. Coresignal repeats the current job in `active_experience_*` fields and marks it in `experience[]` with `active_experience` set to `1`. CompanyEnrich returns one `experiences` list and marks current jobs with `isCurrent`. A person can have more than one current job. After a lookup by work email with [`POST /v2/people/enrich`](/api-reference/v2/post-people-enrich), the experience at the email's company has `isMatched` set to `true`. After a search, `isMatched` marks the experience that matched your filters.

Fields under **Contact** come from [`GET /v2/people/{personId}/email`](/api-reference/v2/get-people-personid-email), a separate call that replaces the Contact Enrichment API.

### Country

Coresignal returns full country names in `hq_country` and `location_country`, and ISO 3166-1 alpha-2 codes in `hq_country_iso2` and `location_country_iso2`. CompanyEnrich returns `location.country.code`, the same alpha-2 code, and `location.country.name`, and filters on the code. To convert stored names, look up the codes with [`POST /v2/geo/countries`](/api-reference/v2/post-geo-countries), which is free.

### Growth periods

Coresignal reports headcount change in `employees_count_change` as monthly, quarterly, and yearly counts and percentages. CompanyEnrich filters on growth with `workforceGrowth` periods `m6`, `y1`, and `y2`, as a ratio: 20% growth is `0.2`. To read growth for one company, compare two entries of `workforce.history`, or page further back with [`GET /v2/companies/workforce`](/api-reference/v2/get-companies-workforce).
