The Reverse Email Lookup API takes a work email address and returns the person behind it as a full [person record](/docs/person-schema): name, current position, seniority, department, LinkedIn URL, and work history. Send the address to [`POST /v2/people/enrich`](/api-reference/v2/post-people-enrich).

A lookup costs 5 credits when a person is returned, and nothing when there is no match.

## Look up an email

This request finds the person behind an email address. You need an API key, which you can create at [app.companyenrich.com/access-keys](https://app.companyenrich.com/access-keys).

<CodeGroup>

```bash cURL
curl -X POST https://api.companyenrich.com/v2/people/enrich \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane.doe@stripe.com"
  }'
```

```javascript JavaScript
import { CompanyEnrich } from '@companyenrich/sdk';

const client = new CompanyEnrich(); // reads COMPANYENRICH_API_KEY

const person = await client.people.enrich({ email: 'jane.doe@stripe.com' });

console.log(person.name, person.position);
console.log(person.socials.linkedinUrl);
```

```python Python
from companyenrich import CompanyEnrich

client = CompanyEnrich()  # reads COMPANYENRICH_API_KEY

person = client.people.enrich("jane.doe@stripe.com")

print(person.get("name"), person.get("position"))
print(person["socials"].get("linkedinUrl"))
```

```ruby Ruby
require "companyenrich"

client = CompanyEnrich::Client.new # reads COMPANYENRICH_API_KEY

person = client.people.enrich("jane.doe@stripe.com")

puts person["name"], person["position"]
puts person.dig("socials", "linkedinUrl")
```

```php PHP
<?php

require 'vendor/autoload.php';

use CompanyEnrich\Client;

$client = new Client(); // reads COMPANYENRICH_API_KEY

$person = $client->people->enrich('jane.doe@stripe.com');

echo $person['name'] ?? '', ' ', $person['position'] ?? '', PHP_EOL;
echo $person['socials']['linkedinUrl'] ?? '', PHP_EOL;
```

```bash CLI
companyenrich people enrich jane.doe@stripe.com
```

## How the match works

A lookup has two steps:

1. The API resolves the company from the domain of the email address.
2. It matches a person at that company using common email address patterns, such as `first.last` or `flast`.

The response is the best match. The job at the email's company is marked with `isMatched` set to `true` in `experiences`, so you can tell which employer the address belongs to.

Because the lookup starts from the company behind the domain, it is built for work email addresses.

## Request fields

| Field    | Value            | Description                                                                         |
| -------- | ---------------- | ----------------------------------------------------------------------------------- |
| `email`  | string, required | The email address to look up. Up to 320 characters.                                 |
| `expand` | array of strings | Paid data to add to the person: `education`, `company`, or both.                    |

## Add the employer's profile or education

| Expansion   | Adds                                                                                               | Extra credits                 |
| ----------- | -------------------------------------------------------------------------------------------------- | ----------------------------- |
| `company`   | The standard company profile for each employer in `experiences`, in place of the short summary.    | 1 per unique company expanded |
| `education` | The person's education history: schools, degrees, and years.                                       | 1                             |

The `company` expansion covers every employer in the person's work history, current and past, so it can add several credits to one lookup. A lookup can expand at most 500 unique companies.

Without the expansion, each experience still names the employer with a short summary: `id`, `name`, `domain`, `logoUrl`, and `industry`.

## When there is no match

The API returns `404` when no person matches the email address. A `404` costs nothing.

The SDKs raise a not-found error for this response. See [Handle an email with no match](/docs/reverse-email-lookup-api-examples#handle-an-email-with-no-match).

## Look up many emails

The lookup takes one email address per request. To process a list, send one request per address, and count on some of them returning `404`. The CLI accepts several addresses at once, or a file with one address per line.

See [Look up a list of emails](/docs/reverse-email-lookup-api-examples#look-up-a-list-of-emails).

## What a lookup costs

* 5 credits when a person is returned.
* 1 more for `education`, and 1 for each unique company expanded with `company`.
* Nothing when no person matches.

See [Credits](/docs/credits) for every price.

## Common questions

### Am I charged when no person is found?

No. A lookup with no match returns `404` and costs nothing.

### Can I get the company without the person?

If you only need the company, enrich the email's domain with the [Company Enrichment API](/docs/company-enrichment-api), which costs 1 credit. To get the person and the full company profile together, add the `company` expansion to the lookup.

### How do I know which employer the email belongs to?

Find the entry in `experiences` where `isMatched` is `true`. That is the job at the company behind the email's domain.

### How sure is the match?

The API returns the best match for the address at that company, based on common email address patterns. Check the name and the matched job against what you already know before you rely on it.

### Can I look up several emails in one request?

No. Send one request per email address. The CLI accepts a list and sends the requests for you.

### Can I go the other way, from a person to their email?

Yes. Use the work email lookup, [`GET /v2/people/{personId}/email`](/api-reference/v2/get-people-personid-email). See [Get a work email for a person you found](/docs/people-search-api-examples#get-a-work-email-for-a-person-you-found).
