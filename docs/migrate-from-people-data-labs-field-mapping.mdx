This page maps the fields of a People Data Labs (PDL) v5 company or person record to the CompanyEnrich V2 [company record](/docs/company-schema) and [person record](/docs/person-schema). Use it to rewrite the code that reads enrichment responses and to migrate stored records.

The same mapping is available as JSON at [/migrations/people-data-labs.json](https://docs.companyenrich.com/migrations/people-data-labs.json), for scripts and [coding agents](/docs/migrate-from-people-data-labs-agent).

## How to read this page

Paths use dots for nested objects and `[]` for arrays, as in `experiences[].company.domain`. **Expand** names the [expansion](/docs/credits#expansions) you must request to get the field. Each one adds credits.

**Fidelity** describes how the definitions compare:

{/* generated: people-data-labs fidelity */}

| Fidelity | Meaning |
| --- | --- |
| `same` | Same field name, meaning, and values. |
| `renamed` | Same meaning under a different name or path. |
| `transformed` | Same information in a different shape, format, or casing. Convert it in code. |
| `lossy` | Related information with a different definition, scale, or granularity. Review before you rely on it. |
| `none` | No CompanyEnrich equivalent. |

{/* end generated */}

Fidelity compares definitions, not data. The two providers build their records from different sources, so a value can differ even when the fields mean the same thing.

### Size and headcount

| People Data Labs | CompanyEnrich | Expand | Fidelity | Notes |
| --- | --- | --- | --- | --- |
| `size` | `employees` |   | lossy | PDL `size` is the range the company selected on its social profile. CompanyEnrich `employees` is calculated from its employee data. The self-reported range exists only as the `reportedEmployees` search filter. See [Company size](#company-size). |
| `employee_count` | `workforce.observedEmployeeCount` | `workforce` | renamed | Both are counted from each provider's people data. Without the expansion, use the `employees` range. |
| `employee_count_by_month` | `workforce.history[].observedEmployeeCount` | `workforce` | transformed | An object keyed by `YYYY-MM` becomes an array of monthly entries, newest first, 12 months per page. Page back with `GET /v2/companies/workforce`. |
| `employee_count_by_role` | `workforce.departmentHeadcount` | `workforce` | lossy | PDL job roles against 14 CompanyEnrich departments. |
| `employee_growth_rate` | — |   | none | Compute it from `workforce.history`. Search by growth with the `workforceGrowth` filter. |
| `employee_count_by_country` | — |   | none |   |
| `inferred_revenue` | `revenue` |   | lossy | Different range boundaries. `revenue` is in the base record. See [Revenue](#revenue). |

## Person fields

Fields under **Current job** and **Current company** come from the person's current experience. A CompanyEnrich person can have more than one current experience, marked with `isCurrent`. After an email lookup, the experience at the email's company has `isMatched` set to `true`.

## Value translations

These tables translate fixed values. Values not listed have no counterpart. Use them to convert stored values and search filters, and keep the original PDL value when you store converted data.

People Data Labs `size`, `job_company_size` → CompanyEnrich `employees`, `reportedEmployees`. The labels translate one to one. The meaning depends on the field: PDL `size` is self-reported, so search it with `reportedEmployees`; CompanyEnrich `employees` is calculated.

### Country

PDL returns a lowercase country name, such as `united states`. CompanyEnrich returns `location.country.code`, an ISO 3166-1 alpha-2 code such as `US`, and `location.country.name`. To convert stored names, look up the codes with [`POST /v2/geo/countries`](/api-reference/v2/post-geo-countries), which is free.
