This page maps the fields Explorium returns for businesses and prospects to the CompanyEnrich V2 [company record](/docs/company-schema) and [person record](/docs/person-schema). Use it to rewrite the code that reads Explorium responses and to migrate the records you stored.

Business fields come from firmographics, fetch, and the technographics, webstack, workforce trends, and funding enrichments. Prospect fields come from fetch, profiles, and contact information. Field names are the same in v1 and v2 unless a row lists both.

The same mapping is available as JSON at [/migrations/explorium.json](https://docs.companyenrich.com/migrations/explorium.json), for scripts and [coding agents](/docs/migrate-from-explorium-agent).

## How to read this page

Paths use dots for nested objects and `[]` for arrays, as in `experiences[].company.domain`. **Expand** names the [expansion](/docs/credits#expansions) you must request to get the field. Each one adds credits.

**Fidelity** describes how the definitions compare:

{/* generated: explorium fidelity */}

| Fidelity | Meaning |
| --- | --- |
| `same` | Same meaning and format. |
| `renamed` | Same meaning and values under a different name or label. |
| `transformed` | Same information in a different format, casing, or structure. Convert it in code. |
| `lossy` | Related but not equivalent. Values can differ, so check the fields your code depends on. |
| `none` | No CompanyEnrich equivalent. |

{/* end generated */}

Fidelity compares definitions, not data. The two providers build their records from different sources, so a value can differ even when the fields mean the same thing.

## Prospect fields

Fields under **Current job** come from the person's current experience. A CompanyEnrich person can have more than one current experience, marked with `isCurrent`. After an email lookup, the experience at the email's company has `isMatched` set to `true`.

Fields under **Contact** come from [`GET /v2/people/{personId}/email`](/api-reference/v2/get-people-personid-email), a separate call.

Person responses include structured `location.state` and `location.city` once the reported location has been resolved. Handle missing values; `location.address` holds the location as text, in a standard form when it names a city or a more precise place and otherwise as reported. The structured objects contain integer IDs you can reuse in [people search filters](/docs/migrate-from-explorium-search#person-states-and-cities).

### Country

Explorium returns a lowercase country name, such as `united states`, and takes lowercase ISO codes in filters, such as `us`. CompanyEnrich returns `location.country.code`, an uppercase ISO 3166-1 alpha-2 code such as `US`, and `location.country.name`. To convert stored names, look up the codes with [`POST /v2/geo/countries`](/api-reference/v2/post-geo-countries), which is free.

### Company age

Explorium filters by age ranges such as `0-3` and `20+`. CompanyEnrich returns `foundedYear` and filters on it with `min` and `max`. Subtract the range from the current year.
