This guide is for engineers whose code or AI agents call Explorium's AgentSource API, v1 or v2, or its MCP server. It maps each Explorium endpoint and MCP tool to CompanyEnrich, lists the behavior that changes in your code, and shows how to check the result on records you already have.

<Warning>
  Explorium says AgentSource will be discontinued on December 2, 2026. Read [Explorium's notice](https://www.explorium.ai/blog/news-and-updates/farewell-from-explorium-with-gratitude/) for what happens to your credits and account.
</Warning>

<Note>
  Explorium behavior on these pages was checked against Explorium's public developer documentation for AgentSource v1 and v2 on November 16, 2026. CompanyEnrich behavior comes from the [V2 API reference](/api-reference/v2/overview). The full mapping is also available as JSON at [/migrations/explorium.json](https://docs.companyenrich.com/migrations/explorium.json).
</Note>

## Switch company enrichment in five minutes

This is the shortest path: a business match and firmographics call, replaced by one enrichment call with the Python SDK.

<Steps>
  <Step title="Get an API key">
    Create a key at [app.companyenrich.com/access-keys](https://app.companyenrich.com/access-keys) and export it as `COMPANYENRICH_API_KEY`. Check it with [`GET /v2/me`](/api-reference/v2/get-me), which is free:

    ```bash
    curl https://api.companyenrich.com/v2/me \
      -H "Authorization: Bearer $COMPANYENRICH_API_KEY"
    ```
  </Step>
  <Step title="Install the SDK">
    ```bash
    pip install companyenrich
    ```

    The [Python SDK](/docs/python-sdk) needs Python 3.10 or later. There are also SDKs for [JavaScript](/docs/javascript-typescript-sdk), [Ruby](/docs/ruby-sdk), and [PHP](/docs/php-sdk).
  </Step>
  <Step title="Replace the calls">
    <CodeGroup>

    ```python Before (Explorium)
    import os

    import requests

    BASE = "https://api.explorium.ai/v2"
    HEADERS = {"api_key": os.environ["EXPLORIUM_API_KEY"]}

    match = requests.post(f"{BASE}/businesses/match", headers=HEADERS,
                          json={"businesses_to_match": [{"domain": "stripe.com"}]}).json()
    business_id = match["matched_businesses"][0]["business_id"]
    if business_id:
        result = requests.post(f"{BASE}/businesses/firmographics/enrich", headers=HEADERS,
                               json={"business_ids": [business_id]}).json()
        company = result["data"][0]["data"]
        print(company["name"], company["number_of_employees_range"], company["linkedin_profile"])
    ```

    ```python After (CompanyEnrich)
    from companyenrich import CompanyEnrich, NotFoundError

    client = CompanyEnrich()  # reads COMPANYENRICH_API_KEY

    try:
        company = client.companies.enrich("stripe.com")
        socials = company.get("socials") or {}
        print(company.get("name"), company.get("employees"), socials.get("linkedinUrl"))
    except NotFoundError:
        company = None  # no match, not charged
    ```

    ```bash cURL
    curl "https://api.companyenrich.com/v2/companies/enrich?domain=stripe.com" \
      -H "Authorization: Bearer $COMPANYENRICH_API_KEY"
    ```

    </CodeGroup>
  </Step>
  <Step title="Update the fields you read">
    | Explorium field | CompanyEnrich field | Change |
    | --- | --- | --- |
    | `business_id` | `id`, or the domain | A different ID. Store the domain or the CompanyEnrich ID. |
    | `name` | `name` | Same |
    | `website` | `domain` or `website` | `domain` is the host. `website` is a full URL. |
    | `number_of_employees_range` | `employees` | Different labels above 500, such as `1K-5K` |
    | `country_name` | `location.country.name` or `location.country.code` | Name in source casing, or an ISO code |
    | `linkedin_profile` | `socials.linkedinUrl` | Full URL with `https://` |

    The [field mapping](/docs/migrate-from-explorium-field-mapping) covers every other field.
  </Step>
  <Step title="Handle no match">
    Explorium's match returns `200` with a `business_id` of `null`. CompanyEnrich returns `404`, and the SDK raises `NotFoundError`. It is not charged.
  </Step>
</Steps>

## Move your MCP setup

If your agent uses the Explorium MCP server, point it at the CompanyEnrich server instead. The hosted server is at `https://mcp.companyenrich.com/mcp`. For example, in Claude Code:

```bash
claude mcp add --transport http companyenrich https://mcp.companyenrich.com/mcp
```

The [MCP server guide](/docs/mcp-server) covers Claude Desktop, Cursor, VS Code, and other clients, and lists the credits each tool uses. Then update any prompts or code that name Explorium tools:

CompanyEnrich tools take plain values, such as a domain or a job title, so your agent does not need to look up IDs or autocomplete values first.

## Endpoint mapping

## Request and response differences

### Authentication

| | Explorium | CompanyEnrich |
| --- | --- | --- |
| Header | `api_key: YOUR_EXPLORIUM_API_KEY` | `Authorization: Bearer YOUR_API_TOKEN` |
| SDK | None | `CompanyEnrich()` reads `COMPANYENRICH_API_KEY`, or takes the key as its first argument |

### From match and enrich to one call

Explorium works in two steps: match a business or prospect to get its ID, then pass the ID to each enrichment you need. v2 can also match and enrich in one call with `businesses_to_match`.

CompanyEnrich returns the record from the lookup itself:

* Enrich a company by domain with [`GET /v2/companies/enrich`](/api-reference/v2/get-companies-enrich), or by name or social profile with [`POST /v2/companies/enrich`](/api-reference/v2/post-companies-enrich).
* Add data with the `expand` parameter instead of separate enrichment calls: `technologies`, `financial`, `workforce`, `keywords`, or `naicsCodes`.
* Enrich a person by work email with [`POST /v2/people/enrich`](/api-reference/v2/post-people-enrich), or find people with [people search](/api-reference/v2/post-people-search).

### Response shape

| Call | Explorium | CompanyEnrich |
| --- | --- | --- |
| Match | `matched_businesses` or `matched_prospects`, each with an `input` and an ID | No match step |
| Enrichment | v2: `data`, a list of `business_id` and `data` pairs. v1: one `data` object. | The record is the body |
| Batch enrichment | Up to 50 IDs per request, in `data` | `items`, each with `domain`, `status`, and `company` when `status` is `found` |
| Fetch | `data`, `total_results`, and `page` | `items` and `nextCursor`. Get totals from the free count endpoint. |
| Errors | `details` and a `correlation_id`. Validation errors return `422` with a `detail` list. | A problem document with `type`, `title`, `status`, and `detail`. `422` adds `errors` per field. The `x-trace-id` header identifies the request. |

### Status codes

| Status | CompanyEnrich |
| --- | --- |
| `200` | A match, or a search that ran |
| `400` | Malformed request |
| `401` | Missing or invalid key |
| `402` | Out of credits, or the plan does not include the request. Do not retry. |
| `403` | The key may not perform this request |
| `404` | No match. Not charged. |
| `422` | Validation failed. `errors` lists the messages per field. |
| `429` | Rate limit hit. Wait for the time the response gives. |

Two differences need code changes. Explorium reports a missed match inside a `200` response, as a `null` ID, while CompanyEnrich returns `404`. Explorium returns `403` when your credits run out, while CompanyEnrich returns `402`. The SDK raises a typed exception for each non-2xx status, such as `NotFoundError`, `PaymentRequiredError`, and `RateLimitError`.

### Billing behavior that affects your code

These differences change how you write retries, guards, and tests. Prices for each endpoint are in [Credits](/docs/credits).

* **No match is free.** Enrichment that finds nothing returns `404` and is not charged.
* **An empty search is charged.** A search with no results costs one result's base price, such as 1 credit for a filter search. Check a new filter with the free [count endpoint](/api-reference/v2/post-companies-search-count) first.
* **Extra company fields are expansions.** The base record excludes `financial`, `keywords`, `naicsCodes`, `technologies`, and `workforce`. Each one you request adds 1 credit per company returned, so request only the ones your code reads.
* **Work emails are a separate call.** [`GET /v2/people/{personId}/email`](/api-reference/v2/get-people-personid-email) costs 10 credits only when it finds an email your account has not accessed before.
* **Responses report their cost.** Read `x-credit-cost` and `x-credit-remaining` from the response headers.

### Pagination

| | Explorium | CompanyEnrich |
| --- | --- | --- |
| Page size | `page_size`, up to 500 | `pageSize`, 1 to 100 |
| Next page | `page`, or the `next_cursor` from the last response | Send the `nextCursor` from the last response as `cursor` |

On CompanyEnrich, `nextCursor` is omitted on the last page, and a cursor expires 24 hours after the first page. The Python SDK pages for you with `search_all()`.

### Rate limits

Explorium counts each ID in a request toward 200 queries per minute. CompanyEnrich counts requests: a global limit of 500 requests per minute per IP address, and a per-route limit from your plan, reported in `x-ratelimit-limit`, `x-ratelimit-remaining`, and `x-ratelimit-window`. A batch of 50 domains is one request. The SDKs wait and retry on `429`. See [Rate limits](/docs/rate-limit).

### Text, URLs, and codes

| | Explorium | CompanyEnrich |
| --- | --- | --- |
| Place names | Lowercase, such as `united states` and `seattle` | Source casing |
| Country codes | Lowercase in filters, such as `us` | Uppercase ISO 3166-1 alpha-2, such as `US` |
| Company websites | Often a bare domain | `domain` is the host, and `website` is a full URL |
| LinkedIn URLs | Sometimes without a scheme. Person URLs can use a member ID, such as `linkedin.com/in/ACoAA...`. | Full URL, such as `https://www.linkedin.com/company/stripe` |

### IDs

Explorium IDs and CompanyEnrich IDs are separate. CompanyEnrich company IDs are UUIDs, and person IDs are 64-bit integers. Store the CompanyEnrich ID next to the Explorium ID, and re-key company data on its domain.

## Verify parity on your own data

Measure CompanyEnrich on records you already have before you switch. This makes no Explorium requests, so it works after AgentSource is discontinued.

<Steps>
  <Step title="Check your key and plan">
    Call [`GET /v2/me`](/api-reference/v2/get-me). It is free and returns your balance and plan capabilities.
  </Step>
  <Step title="Size your searches for free">
    Send each translated filter to the [company](/api-reference/v2/post-companies-search-count) or [people](/api-reference/v2/post-people-search-count) count endpoint and compare `total` with Explorium's `total_results`.
  </Step>
  <Step title="Pick a sample">
    Take 100 to 200 firmographics records you already stored from Explorium. CompanyEnrich charges 1 credit per company found.
  </Step>
  <Step title="Compare the fields you read">
    Run the script below on the sample. It enriches the domains in batches of 50 and sorts each field into `equal`, `differ`, `only Explorium`, `only CompanyEnrich`, or `both empty`. Fields marked `lossy` in the [field mapping](/docs/migrate-from-explorium-field-mapping) differ by definition, so leave them out or compare them by hand.
  </Step>
  <Step title="Check searches and people">
    For each translated search, run the count, then a [preview](/api-reference/v2/post-companies-search-preview) if your plan includes it, then one page. For person lookups, test work emails you already know.
  </Step>
</Steps>

<Accordion title="compare.py" icon="code">

```python compare.py
"""compare.py: compare stored Explorium firmographics with CompanyEnrich on the same domains.

Usage: python compare.py explorium_companies.jsonl   (one stored firmographics record per line)
Costs 1 CompanyEnrich credit per company found. Makes no Explorium requests.
"""

import json
import sys
from collections import Counter

from companyenrich import CompanyEnrich

SIZES = {"501-1K": "501-1000", "1K-5K": "1001-5000", "5K-10K": "5001-10000", "over-10K": "10001+"}

# Explorium field -> how to read the comparable CompanyEnrich value
FIELDS = {
    "name": lambda c: c.get("name"),
    "website": lambda c: c.get("domain"),
    "country_name": lambda c: ((c.get("location") or {}).get("country") or {}).get("name"),
    "city_name": lambda c: ((c.get("location") or {}).get("city") or {}).get("name"),
    "number_of_employees_range": lambda c: SIZES.get(c.get("employees"), c.get("employees")),
    "linkedin_profile": lambda c: (c.get("socials") or {}).get("linkedinUrl"),
}


def domain(website):
    host = website.lower().removeprefix("https://").removeprefix("http://").removeprefix("www.")
    return host.split("/")[0]


def normalize(value):
    if isinstance(value, str):
        value = value.lower().removeprefix("https://").removeprefix("http://").removeprefix("www.").rstrip("/")
    return value or None


def outcome(explorium, ce):
    if explorium is None and ce is None:
        return "both empty"
    if ce is None:
        return "only Explorium"
    if explorium is None:
        return "only CompanyEnrich"
    return "equal" if explorium == ce else "differ"


def main(path, client=None):
    records = [json.loads(line) for line in open(path) if line.strip()]
    records = [record for record in records if record.get("website")]
    client = client or CompanyEnrich()  # reads COMPANYENRICH_API_KEY
    results = Counter()
    for start in range(0, len(records), 50):
        chunk = records[start:start + 50]
        batch = client.companies.enrich_batch([domain(record["website"]) for record in chunk])
        for record, item in zip(chunk, batch["items"], strict=True):
            if item["status"] != "found":
                results[f"lookup: {item['status']}"] += 1
                continue
            for field, read in FIELDS.items():
                results[f"{field}: {outcome(normalize(record.get(field)), normalize(read(item['company'])))}"] += 1
    for key, count in sorted(results.items()):
        print(f"{key:45} {count}")
    return results


if __name__ == "__main__":
    main(sys.argv[1])
```

## Cut over

* Put the CompanyEnrich path behind a feature flag, and switch it on before Explorium stops serving requests.
* Store CompanyEnrich IDs next to Explorium IDs, and keep the Explorium values you stored.
* Log `x-credit-cost` per call for the first weeks.
* Remove the Explorium client, keys, and MCP configuration once nothing calls them.

## What has no equivalent

Plan a replacement for these, because there is no Explorium to fall back on:

| Explorium feature | What you can do |
| --- | --- |
| Business and prospect events, enrollments, and webhooks | Re-enrich the companies and people you track on a schedule, and compare `updatedAt`, headcount, funding, or `currentPositionStartDate`. |
| Phone numbers, personal emails, and hashed emails | Use another provider. CompanyEnrich finds work emails. |
| Prospect match by LinkedIn URL or phone number | Match by work email, or search by name at the company's domain. |
| Fetch and stats breakdowns | Run one free count per segment. |
| Bombora intent, 10-K analysis, employee ratings, website changes, website keyword search, and LinkedIn posts | Use another provider. |
| Company hierarchies and financial indicators | Use another provider. `expand=financial` returns the stock symbol, exchange, and funding. |
| Research endpoints | Give your own agent the [MCP server](/docs/mcp-server) with your other tools. |
| Person location below country level, skills, interests, and contact availability filters | Filter in your code after the search. |

## Common questions

<AccordionGroup>
  <Accordion title="Can I keep using my Explorium business IDs?">
    No. Store the CompanyEnrich ID alongside the Explorium ID, and re-key company data on its domain.
  </Accordion>
  <Accordion title="Do I need to match before I enrich?">
    No. Send the domain, or the name or a social profile, and the record comes back in the same response.
  </Accordion>
  <Accordion title="Is there an equivalent of each Explorium enrichment?">
    Firmographics, technographics, funding, workforce trends, and lookalikes have one, with fewer fields. See the [endpoint mapping](#endpoint-mapping) for the rest.
  </Accordion>
  <Accordion title="Can I get phone numbers?">
    No. CompanyEnrich finds work emails with [`GET /v2/people/{personId}/email`](/api-reference/v2/get-people-personid-email).
  </Accordion>
  <Accordion title="How do I get the total number of results?">
    Send the same filter to the free count endpoint. Search responses do not include a total.
  </Accordion>
  <Accordion title="Do batch and bulk enrichment need a specific plan?">
    No. Batch and bulk enrichment work on every plan.
  </Accordion>
  <Accordion title="Why are place names in a different case?">
    Explorium lowercases place names. CompanyEnrich returns the source casing. Lowercase values yourself if your code compares strings.
  </Accordion>
</AccordionGroup>
